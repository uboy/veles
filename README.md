# Veles

**База знаний с RAG и верифицируемыми цитатами** — для себя и для небольшой
компании. Единый поиск по своим документам (pdf, docx, pptx, xlsx, txt/md),
ответы языковой модели, где каждое утверждение снабжено ссылкой на
первоисточник — файл, страницу, пункт документа. Опоры в документах нет —
система честно отвечает «фактов нет», вместо того чтобы выдумывать.

Работает локально: тексты остаются на вашей машине, поисковые индексы
строятся и перестраиваются на ней же. Языковая модель — любая
OpenAI-совместимая: локальная (llama.cpp, Ollama) или облачная по вашему
выбору; для поиска модель не нужна вовсе.

## Что внутри

- **Гибридный поиск** — векторный (multilingual-e5-small) + лексический BM25,
  слияние RRF, буст совпадений по названию документа. Один движок для всех
  клиентов: CLI, REST, веб-чат, Telegram.
- **Цитаты с точным адресом** — PDF: страница и область на ней; PPTX: слайд;
  XLSX: лист и диапазон; Markdown: заголовок и строки. Пересказы и
  транскрипции помечены как производные и первоисточником не притворяются.
- **Честный отказ** — гейт ответности: на вопрос без опоры в документах
  возвращается отказ, а не правдоподобная фантазия.
- **Жизненный цикл документов** — версии и ревизии, устойчивые идентификаторы
  пунктов (сравнение редакций одного пункта), удаление без фантомов в поиске,
  пометка «утратил силу» с предупреждением «⚠ Норма утратила силу» в ответах.
- **Права и изоляция** — личные документы видит только владелец; групповые —
  только члены группы; проверка прав происходит до поиска, группы выводятся
  сервером из проверенной личности, а не принимаются от клиента.
- **Интерфейсы** — CLI (`veles add/ask/serve/...`), REST API с OpenAPI
  и Swagger UI из коробки, фасад `/v1/chat/completions` для Open WebUI и
  других OpenAI-совместимых клиентов, Telegram-бот.

## Безопасность и приватность

- **Local-first.** Поиск целиком локальный (локальный эмбеддер + BM25);
  канон документов и индексы — у вас; наружу не уходит ничего, кроме
  запросов к выбранной вами LLM, а она может быть локальной.
- **Авторизация до поиска.** Отсечение по правам — до формирования контекста
  запроса, а не фильтрация результатов после.
- **Подписанные ссылки.** Ссылки на источники в цитатах подписаны секретом
  сервера: подделать адрес или перелинковать цитату на чужой документ нельзя.
- **Защита от перегрузки.** Скользящее окно rate-limit по пользователю и
  токену; для публикации наружу — TLS-профиль (caddy) и изоляция внутренних
  портов.
- **Загрузка под контролем.** Проверка целостности файлов, каждое задание
  загрузки возвращает статус и причину отказа; удалённый документ исчезает
  из поиска немедленно и без рестарта.

## Быстрый старт

### Windows — установка в один клик

Скачайте сборку, запустите `install.cmd` — программа ставится в профиль
пользователя, встаёт в автозагрузку и поднимает REST API; данные живут
отдельно и переживают обновление и удаление программы. Подробности и путь
из исходников — [docs/RUN-WINDOWS.md](docs/RUN-WINDOWS.md).

### Из исходников (Windows/macOS/Linux)

```bash
git clone https://github.com/uboy/veles.git && cd veles
pip install -e ".[st,faiss]"       # поиск по смыслу + быстрый векторный поиск
veles add инструкция.md            # первый документ: индекс создастся сам
veles ask "что сказано про ...?"   # ответ с цитатами
veles serve                        # REST API на http://127.0.0.1:8400
```

Языковая модель настраивается в `.env` рядом с данными: `VELES_LLM_BASE_URL`,
`VELES_LLM_MODEL` (примеры для llama.cpp, Ollama и облачных API — в
`config.example.env`). Без модели поиск и REST работают; текстовые ответы
появятся после подключения модели. Эмбеддер поиска скачивается при первом
запуске, дальше всё работает офлайн.

### Демо за 5 минут (корпоративный комплект)

```bash
tar xzf veles-deploy-kit-<версия>.tar.gz && cd veles-deploy-kit-<версия>/deploy/kit
./install.sh --demo --yes
./veles ask "Сколько дней отпуска положено сотруднику?"
```

Дальше: три профиля развёртывания (lite / personal / corporate), TLS, группы
доступа, Open WebUI, Telegram — [deploy/kit/README.md](deploy/kit/README.md).

## API и интеграции

- `POST /v1/knowledge/query` — основной API: ответ, доказательства, цитаты,
  вердикт ответности. `POST /v1/documents` — загрузка файлов. Схема и
  Swagger UI — `http://localhost:8400/docs` (то же приложение отдаёт
  OpenAPI-описание всех методов).
- `POST /v1/chat/completions` — совместимость с OpenAI-клиентами: веб-чат
  (Open WebUI) и любые агентские фреймворки подключаются как к обычной
  модели, изоляция личных документов соблюдается и в чате.
- Telegram-бот: вопрос в чат — ответ со ссылками на источники.
