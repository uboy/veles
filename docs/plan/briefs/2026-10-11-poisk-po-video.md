# Бриф: поиск по видео

- **Дата:** 2026-10-11. **Владелец:** Denis Mazur (го в чате).
- **Эпик:** poisk-po-video. **Карточка:** ai-tracker `work/veles/task-veles-video-search.md` (in_progress).
- **Ветка:** feature/video-search, worktree `~/proj/veles-video`.

## Что делаем

Видео-файл (mp4/mkv/mov/webm/m4v/avi) ингестится в veles: аудиодорожка
транскрибируется сервисом VoxFusion (сегменты с таймкодами), сегменты сливаются
в узлы канона с локатором t_start/t_end (секунды), узлы попадают в общий
гибридный индекс. Цитаты ответов несут таймкод («00:12:34»). Ключевые кадры
извлекаются ffmpeg как активы документа (просмотр через /v1/asset); CLIP-индекс
кадров - вне скоупа, ждёт решения по модели канала изображений.

## Почему так (решения дизайна, согласованы владельцем)

- Речь -> текст: LLM текстовая, цитата обязана быть проверяемым текстом;
  эмбеддинг аудио не даёт цитируемого содержимого (разбор - в чате 11.10).
- VoxFusion, а не Whisper внутри veles: сервис уже в проде (bm1:8500,
  диаризация), контракт include_segments проверен живым пробником 11.10;
  та же пара env, что у Telegram-моста (VOXFUSION_API_URL/VOXFUSION_API_TOKEN).
- Расшифровки в ОБЩИЙ индекс: обычный текст, сквозной поиск «документ + место
  в видео»; изоляция медиа в отдельную базу владельцем не выбрана.
- Fail-closed без токена: понятная причина отказа джобы, тихой деградации нет.

## Не делаем (границы)

- CLIP-индексация кадров (ждёт модель канала изображений).
- Диаризация в цитатах (кто говорил) - сегменты уже с спикерами, если сервис
  отдаёт; в текст узла включаем, отдельной структуры не строим.
- Нативная векторизация видео как видео.

## Риски

- ffmpeg обязателен на машине ингеста (проверка shutil.which, отказ с причиной).
- Долгая транскрибация длинных видео - поллинг с таймаутом из env (дефолт
  1800 с), джоба остаётся честной (статус/ошибка).
- Схема канона расширяется новыми Optional-полями Provenance - старые
  читатели (pydantic) игнорируют неизвестные поля, новые читают старое как None.
