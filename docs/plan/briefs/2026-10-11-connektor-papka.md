## Что делаем

`veles sync --root <dir>`: каталог-источник (txt/md/pdf) сверяется с каноном
по sha256; новые файлы ингестятся, изменённые - новой ревизией (старая
архивируется, K3), удалённые - tombstone (K10). Источник строго read-only.
Документ-идентичность = относительный путь (как у корпусного конвейера),
цитаты ссылаются на исходное место. CLI-флаги: --dry-run (показать дельту,
ничего не меняя), --yes (без подтверждения для автоматизации).

## Почему так

- JTBD P0-1 (work/veles-official-docs/): самый понятный вход - документы
  остаются где лежат; конвейер канона/ревизий/удалений уже есть, добавляется
  только сверка состояния и применение дельты.
- Не демоне и не watcher (это P2 «background ingestion»): sync - явная
  команда; расписание - дело планировщика заказчика (cron).

## Границы

- Без ACL из источников (это P0-2 identity), без SMB-специфики (локальный
  каталог и смонтированная SMB-папка неотличимы для файловых операций).
- Без манифестов-allowlist: sync - для каталогов заказчика, где allowlist
  не существует; контракт «источник читается, канон пишется» сохраняется.

## Риски

- Симлинки и выходы за корень каталога - обязательный негативный тест.
- Долгий разбор PDF - существующая изоляция парсера покрывает.
- Гонка двух sync одновременно - файловый лок (см. INDEX_LOCK паттерн).
