# План: журнал аудита действий (кто, когда, что)

> Заказ владельца 12.10: «аудит и логирование в админке должно быть - что
> когда и кем произошло, включая все действия в админке и все действия
> пользователей, включая пользовательский поиск». Бриф:
> docs/plan/briefs/2026-10-12-admin-audit.md

## Фаза 1. Журнал и точки записи (бэкенд)

Цель: append-only журнал событий в каталоге данных + запись во все
значимые действия.
Файлы: `veles/audit.py` (новый) - класс AuditLog: JSONL в
`<VELES_DATA>/audit/audit.jsonl`, событие {ts ISO-8601 UTC, actor, admin,
action, target, details, ip}; потокобезопасно; never-throw (ошибка записи -
warning, запрос не ломается); ротация по размеру VELES_AUDIT_ROTATE_MB
(дефолт 50, 0=выкл) с хранением VELES_AUDIT_KEEP последних файлов (дефолт 5);
чтение с фильтрами для API.
Точки записи (конвенция действий): auth_ldap_ok/auth_ldap_fail
(app.py:498), search (/v1/knowledge/query, details=текст запроса, обрезка
500), ask (/v1/chat/completions), upload (/v1/documents, target=имя файла),
document_delete, document_regroup (target=document_id, details=новые
группы), job_cancel/job_retry/job_delete (target=job_id),
audit_access_denied (не-админ дёрнул /v1/admin/audit).
Почему расширен каталог: ревью раунд 1 - чтение полного текста (самое
чувствительное действие пользователя) не было в каталоге и не в исключениях;
добавлены document_read (/v1/source: оригинал и сборка канона) и
tracker_read (/tracker/file, details=чей каталог).
НЕ логируем: healthz/readyz/models/stats/static/assets, сами успешные чтения
аудита. Заголовки целиком (Authorization, токены) в журнал не попадают.
actor: RequestIdentity.user_id; пустой = "owner" (bearer-владелец), нет
личности = "anonymous".
Файлы правок: `veles/api/app.py`, `veles/api/documents.py`.
Проверка: юнит-тесты `tests/test_audit.py` - запись/ротация/фильтры/
never-throw (каталог только-чтение); TestClient - поиск пишет search,
upload/delete/regroup/job_* пишут свои события, пароль/токен в журнал не
попадают.

## Фаза 2. API чтения и вкладка «Аудит»

Цель: админ видит журнал в панели.
Файлы: `veles/api/app.py` (GET /v1/admin/audit: параметры actor, action, q -
подстрока по target/details, since, until, limit<=1000 дефолт 100, offset;
только admin, иначе 403), `veles/api/admin_page.html`,
`veles/api/static/admin.js` (вкладка «Аудит»: таблица
время|кто|действие|цель|детали; фильтры действие/кто/подстрока/период;
«Обновить»; «Показать ещё»; экспорт CSV текущей выборки), тесты UI в
`tests/test_admin_ui.py`.
Проверка: тесты фазы 1+2 зелёные; у не-админа 403.

## Фаза 3. Сквозная валидация на живом сервере

Цель: доказать на реальном uvicorn (не TestClient), что журнал пишется и
виден админу.
Файлы: `evals/audit-validate.py` + отчёт
`evals/results/2026-10-12-admin-audit.md`.
Метод: временный VELES_DATA, сервер в identity-режиме с двумя
пользователями (админ и не-админ); сценарии: (а) поиск и вопрос от
пользователя -> события search/ask с текстом; (б) загрузка -> смена групп ->
удаление документа админом -> цепочка upload/document_regroup/
document_delete; (в) не-админ зовёт /v1/admin/audit -> 403 и событие
audit_access_denied; (г) админ читает журнал через API -> видит все события
по порядку, фильтры actor/action/q отсекают правильно; (д) ротация: маленький
VELES_AUDIT_ROTATE_MB -> второй файл создан, старый сдвинут; (е) замер
латентности поиска до/после включения аудита (не должен вырасти заметно).
Проверка: скрипт завершается кодом 0 с финальной строкой VALIDATION-PASS;
отчёт с фактическими выводами команд.

## Фаза 4. Независимое ревью и финал

Цель: ревью без блокирующих находок; полный pytest зелёный.
Фокус ревью: полнота покрытия (какое действие осталось незалогированным),
утечки секретов в журнал, append-only и never-throw, доступ к журналу только
у админа, влияние на латентность горячего пути (поиск), корректность
ротации, XSS в рендере деталей на вкладке (esc на всех стоках).
Проверка: ревью без high/medium; полный набор зелёный; после ленда в main -
CI GitHub зелёный.
