# План: поиск по изображениям — отдельный индекс со слиянием результатов

Дата: 2026-10-08. Статус: в работе.
Связанные документы: `docs/adr/2026-10-07-vybor-steka-bazy-znaniy.md` (стек),
`evals/results/2026-10-07-eg2-embedding-bench.md` (замер универсальной модели).

## Зачем

В базе знаний есть изображения внутри документов: схемы и диаграммы в книгах,
картинки в вики-страницах. Текстовый поиск их не видит: вопрос «покажи схему
сборки» не находит страницу с нужной картинкой, если слова вопроса не
встречаются в подписи.

Замена текстовой модели на универсальную (текст и картинки в одном векторном
пространстве) отвергнута замером от 07.10.2026: на наборе из 50 статей полнота
топ-5 упала с 1.000 до 0.800 (10 промахов против нуля), точность первого места
— с 0.600 до 0.420; на золотом наборе (57 вопросов) точность первого места
упала с 0.860 до 0.807. Универсальная модель проигрывает специализированной
текстовой, поэтому текстовый канал не трогаем.

Решение: изображения индексируются отдельной мультимодальной моделью в
отдельный векторный индекс; на запросе ищем по текстовому индексу (как сейчас)
и по картинному, результаты сливаются взаимным рангом; картинки приходят в
ответе отдельным типом цитат со ссылкой на файл.

## Первичное решение по модели (пересматривается после фазы 0)

- Основной кандидат: jina-clip-v2 — мультиязычная модель «текст-картинка»
  (понимает русские запросы к изображениям), лицензия Apache-2.0,
  программируемая размерность векторов.
- Точностной гейт (фаза 0): на небольшой размеченной выборке изображения
  правильной книги обязаны попадать в топ-3 по русским запросам темы книги
  не хуже 80% запросов.
- Гейт развертывания (фазы 0 и 3): кодировщик текстовых запросов обязан
  работать на хосте сервиса в доступной памяти; замер памяти и задержки
  фиксируется. Не проходит — доклад владельцу с цифрами и кандидатами на
  замену (jina-clip-v1 и легче); замену выбирает владелец.

## Фазы

### Ф0. Санити модели на реальных картинках корпуса (замер до кода)

- Цель: убедиться, что модель связывает русские вопросы с содержимым картинок
  из нашего корпуса, до написания интеграционного кода.
- Файлы: `scripts/image_sanity.py`, отчёт в `evals/results/`.
- Критерий: на двух книгах разных тем (около 30 извлечённых картинок, по 10
  русских запросов на книгу) картинки правильной книги в топ-3 не хуже 80%
  запросов; модель загружается и на машине с GPU, и на CPU хоста сервиса —
  с замером памяти и задержки на запрос.
- Проверка: скрипт + журнал прогона в `evals/results/`; вердикт вписывается
  в этот план.
- При провале гейта: не импровизируем — цифры, кандидаты, доклад владельцу.
- **Вердикт (08.10, замер `evals/results/2026-10-08-image-channel-bench.md`):**
  качество: гейт пройден у jina-clip-v2 (топ-3 0.800 ровно порог), у
  jina-clip-v1 провален (0.650). Память на хосте сервиса: v2 проваливает гейт
  (пик 4.4 ГБ против ~2.0 ГБ свободных), v1 проходит (1.6 ГБ, 140 мс/запрос).
  Итог Ф0: архитектура канала готова и проверена E2E, включение упирается в
  развилку модели/развертывания - решение владельца (см. отчёт).

### Ф1. Извлечение изображений из документов

- Цель: получить изображения из корпуса с привязкой к источнику.
- Почему сузилась (08.10): парсер PDF уже извлекает картинки как активы
  документа (`generate_picture_images`, узлы `node_type="image"` с подписью,
  страницы и файлом в `<doc_dir>/assets/`) - требование владельца от 28.09.
  Для PDF отдельное извлечение не нужно: инвентарь строится из готового
  текстового индекса (см. `inventory_from_meta`). Извлечение пишется только
  для вики-клона (вторая итерация канала).
- Файлы: `veles/indexing/image_index.py` (инвентарь), `tests/test_image_index.py`.
- Критерий: из PDF извлекаются растровые картинки (фильтр мелких иконок по
  размеру, дедупликация по хэшу содержимого), каждая с полями: исходный
  документ, страница, группы доступа документа; из клона вики — файлы
  картинок вместе с их страницами-источниками; итог — файл-манифест.
- Проверка: юнит-тесты на собранных образцах; прогон на подмножестве корпуса
  с выборочной ручной проверкой (картинка соответствует странице).

### Ф2. Построение индекса изображений

- Цель: отдельный векторный индекс по извлечённым картинкам.
- Файлы: `veles/indexing/image_index.py`, `scripts/build_image_index.py`,
  `tests/test_image_index.py`.- Критерий: индекс строится тем же хранилищем векторов, что текстовый (свой
  файл и своя размерность); метаданные (источник, страница, группы доступа,
  файл картинки) хранятся рядом; поиск вектором картинки находит саму
  картинку; поиск текстовым вектором запроса выдаёт ожидаемую картинку из
  выборки фазы 0.
- Проверка: юнит-тесты; построение на реальном наборе; число
  проиндексированных картинок сходится с манифестом.

### Ф3. Запрос-путь: слияние каналов в ответе API

- Цель: `/v1/knowledge/query` отдаёт картинки наравне с текстовыми цитатами.
- Файлы: `veles/retrieval/image_retriever.py`, `veles/api/app.py`,
  `veles/config.py`, `tests/test_image_merge.py`.
- Критерий: при включённом картинном индексе ответ содержит цитаты с
  `kind: "image"` (ссылка на файл, источник, страница); без индекса или с
  выключенным каналом (переменная окружения) структура ответа прежняя и
  текстовая выдача не меняется; группы доступа картинки = группы исходного
  документа (картинка закрытого документа не выдаётся группе без доступа);
  файл отдаётся отдельным эндпоинтом с теми же правилами доступа.
- Проверка: юнит-тесты слияния и доступа (положительный и отрицательный
  кейс); E2E на живом сервисе с маленьким индексом; полный набор тестов
  зелёный (регрессия текстового канала).

### Ф4. Показ картинок в веб-интерфейсе

- Цель: пользователь видит картинки в ответах веб-интерфейса.
- Файлы: `integrations/openwebui/functions/veles_knowledge.py`, тесты.
- Критерий: функция веб-интерфейса рендерит `kind: "image"` как изображение
  с подписью источника и ссылкой; при выключенном канале вывод прежний.
- Проверка: юнит-тесты рендера; дымовой прогон в живом веб-интерфейсе.

## Вне объёма первой версии

- Переранжирование объединённой выдачи cross-encoder'ом.
- Индексация изображений, загружаемых пользователями.
- Генерация текстовых описаний картинок для текстового индекса.
