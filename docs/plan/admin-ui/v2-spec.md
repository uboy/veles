# Спека: админка v2 (обратная связь владельца 11.10)

## 1. Группы документов (сейчас группы задаются только при загрузке)
- Backend: новый admin-bearer эндпоинт смены групп документа
  (POST /v1/documents/{document_id}/groups {groups: [...]}): переписывает
  access_groups в манифесте канона (canon store) и в метах узлов живого
  индекса (паттерн overlay-патчей из veles/indexing/overlay.py), права
  применяются немедленно. Админ-only (bearer владельца).
- UI «Документы»: чекбоксы на строках + «выбрать все»; массовая панель
  «сменить группу на: [dropdown групп из /v1/groups]» и «удалить выбранные»
  (цикл по существующим DELETE с прогрессом и подтверждением); смена группы
  у одиночного документа - той же панелью при одном выбранном.

## 2. Задачи (сейчас только просмотр)
- Backend: в IngestQueue добавить cancel(job_id) (queued - снять из очереди;
  running - прервать изолированный дочерний процесс и пометить failed
  «отменена владельцем»), retry(job_id) - повторная постановка сохранённого
  L0-файла, delete(job_id) - убрать запись из журнала задач. Маршруты:
  POST /v1/documents/jobs/{id}/cancel|retry, DELETE /v1/documents/jobs/{id}.
  Дополнить GET /v1/documents/jobs полями: exists_in_base (документ уже в
  каноне), duplicate_of (id другой активной задачи с тем же именем файла).
- UI «Задачи»: кнопки по статусу (Отменить для queued/running, Перезапустить
  для failed, Удалить для любых завершённых), бейджи «уже в базе» и
  «дубль задачи №N», автосписок обновляется без потери состояния.

## Проверки
- Тесты: перегруппировка меняет и канон, и выдачу поиска (doc в группе A
  находит до, в группе B - после; чужая группа не находит); отмена queued;
  retry пересоздаёт задачу; дубликат-индикатор; регресс - старые клиенты.
- Валидация: сквозной сценарий владельца через TestClient/фасад:
  загрузка 2 документов -> массовая смена группы -> поиск подтверждает ->
  массовое удаление -> поиск пуст; задача-фол (битый файл) -> перезапуск ->
  отмена -> удаление из истории.
