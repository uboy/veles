## Фаза 1. Ядро синхронизации

Цель: детерминированная сверка каталога с каноном и применение дельты.
Файлы: `veles/ingest/sync.py` - обход каталога (txt/md/pdf, без симлинк-побегов),
сравнение по sha256 с манифестами канона, дельта {added, updated, deleted,
unchanged}; CLI `veles sync --root <dir> [--dry-run] [--yes]`; удаления через
существующий delete_document (tombstone, K10), обновления через существующий
ingest_document (ревизии, K3). Источник ТОЛЬКО читается.
Проверка: юнит-тесты диффа (без сети/GPU) - новый/изменённый/удалённый/
неизменный файл, симлинк наружу игнорируется, пустой каталог.

Расхождение плана и реальности (почему): «удалённые» - не весь канон минус
источник, а только документы с маркером владения `fsync:<корень>:` в
derived_from: относительный путь не определяет корень, и наивная дельта при
первом sync чужого каталога удалила бы корпусные/user-документы (тест
test_unrelated_canon_docs_not_deleted). Уточнение: на Windows junction - не
is_symlink и os.walk(followlinks=False) по ним циклится, поэтому каталоги
обрезаются по resolve() за корень (тест test_dir_escape_ignored).

## Фаза 2. Сквозная валидация на реальном каталоге

Цель: доказать сценарий заказчика на живом коде (не моки).
Файлы: `evals/results/2026-10-11-source-sync.md` + временный каталог в eval.
Метод: каталог с 3 файлами -> sync -> 3 документа в каноне и поиск находит;
правка файла -> sync -> ревизия r2, старая в архиве; удаление -> sync ->
документ исчез из поиска (tombstone); повторный sync без изменений -> 0 дельта
(идемпотентность). Отчёт с выводами команд.
Проверка: скрипт валидации завершается кодом 0; отчёт с фактическими выводами.

## Фаза 3. Ревью и финал

Цель: независимое ревью (безопасность: побеги пути, гонки, запись в источник;
корректность: идемпотентность, UTF-8, большие файлы) + полный pytest.
Проверка: ревью без блокирующих находок; полный набор зелёный; CI GitHub
зелёный после ленда в main.
