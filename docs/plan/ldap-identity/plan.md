## Фаза 1. LDAP-аутентификация и группы

Цель: пользователь домена входит логином/паролем -> короткоживущий jwt с его
группами veles; права по группам работают в существующем контуре (фильтр до
evidence). Файлы: `veles/policy/ldap_identity.py` (bind пользователя по
DN-шаблону или поиском, чтение групп: memberOf/posixGroup, маппинг
LDAP-групп -> группы veles через VELES_LDAP_GROUP_MAP), маршрут
`POST /v1/auth/ldap` (выдача jwt, существующий verify_hs256), env:
VELES_LDAP_URL / VELES_LDAP_BIND_DN_TEMPLATE / VELES_LDAP_BASE_DN /
VELES_LDAP_GROUP_BASE_DN / VELES_LDAP_GROUP_MAP / VELES_LDAP_TIMEOUT_S.
Конфигурация выключена по умолчанию (fail-closed: нет env - маршрут 404/отключён).
Проверка: юнит- и интеграционные тесты с in-process LDAP-сервером (ldaptor,
тестовая зависимость): успешный вход, неверный пароль -> 401, пользователь
не в маппinged-группах -> пустые группы, отзыв из группы + повторный вход ->
доступа нет.

## Фаза 2. Сквозная валидация

Цель: сценарий ИБ-службы на живом коде: вход -> вопрос видит только своё;
удаление из группы -> новый вход -> чужое невидимо; старый jwt истекает.
Файлы: `evals/results/2026-10-12-ldap-identity.md` + скрипт валидации.
Проверка: скрипт exit 0, отчёт с командами и выводами.

## Фаза 3. Ревью и финал

Независимое ревью (безопасность: инъекции в DN/bind, хранение паролей в логах,
токены, негативные кейсы; корректность маппинга групп) + полный pytest + CI.
