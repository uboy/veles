# Видение проекта Veles

> Статус: принят (2026-10-11). Документ фиксирует, что такое veles, для кого
> он, чем отличается от альтернатив и куда движется. Практические следствия
> для разработки — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Что такое veles

Veles — база знаний с RAG и **верифицируемыми цитатами**: личная и
корпоративная. Система ищет по вашим документам, отвечает языковой моделью и
на каждое утверждение даёт ссылку на первоисточник — файл, страницу, пункт,
таймкод. Если опоры в документах нет — система отвечает отказом, а не
правдоподобной выдумкой. Хранилище — обычные файлы; всё производное
(индексы) перестраивается из них на 100% офлайн.

## Проблема, которую решаем

Корпорации и частные эксперты копят знания в pdf, вики, записях встреч — и не
могут их спрашивать: облачные ИИ-сервисы требуют отдать документы наружу
(юридически неприемлемо для значительной части данных), а самописные
становятся чёрным ящиком без проверки ответов. Рынок enterprise-RAG растёт,
но типовые решения упираются в три вопроса: **куда уходят данные**, **можно ли
проверить ответ** и **что случится с хранилищем, если мы уходим от вендора**.

## Пять принципов

1. **Ответ можно проверить.** Цитата несёт точный адрес источника (страница и
   область PDF, слайд, диапазон листа, строки Markdown, таймкод видео).
   Пересказы и транскрипции помечены как производные и не притворяются
   первоисточником. Нет опоры — честный отказ.
2. **Данные — только ваши.** Поиск целиком локальный; языковая модель —
   любая OpenAI-совместимая, в том числе локальная на вашей видеокарте.
   Наружу не уходит ничего, кроме запросов к выбранной вами модели.
3. **Никакого вендор-лока.** Хранилище истины — файлы в вашем каталоге
   (md/jsonl + исходники); векторные индексы — производный кэш. Перенос базы
   на другую машину или в другой контур = копирование файлов и пересборка
   индексов, без экспортных скриптов и закрытых форматов.
4. **Права проверяются до поиска.** Отсечение документов по правам
   происходит до формирования контекста запроса; группы выводятся сервером
   из проверенной личности и не принимаются от клиента.
5. **Одна кодовая база — три профиля.** Личный (один процесс, офлайн),
   персональный с веб-интерфейсом, корпоративный (сервер, группы, TLS).
   Профиль — конфигурация, не форк.

## Конкурентные преимущества для рынка

- **Безопасность.** Local-first, авторизация до поиска, подписанные ссылки
  на источники (подделать нельзя), rate-limit, TLS-профиль, изоляция личных
  документов (видит только владелец и администратор).
- **Скорость.** Гибридный поиск (векторы + BM25) на CPU: полнота R@5 = 0.98
  на юридическом корпусе 127 500 узлов; накладные расходы буста названий
  1,1 мс на запрос. Ответ с синтезом локальной 31B-модели — 11–19 с; с
  облачной моделью — быстрее. Все цифры — из протоколов в `evals/results/`.
- **Отсутствие вендор-лока.** Смена эмбеддера или LLM — правка конфига, а не
  миграция данных. Уход от veles — ваши файлы остаются файлами. Это отличает
  veles от решений, где знания живут в проприетарной схеме векторной БД.
- **Гибкость.** Любой OpenAI-совместимый клиент (веб-чат, агентский
  фреймворк, Telegram) подключается как к обычной модели. Первичное
  хранилище — ваше: каталог файлов (в том числе git-репозиторий) наполняет
  базу через allowlist-конвейер; парсеры — адаптеры, добавление формата не
  меняет ядро.
- **Контроль прав.** Личные документы видит только владелец; групповые —
  только члены группы; в чате от чужого имени (act-as) обычный пользователь
  ищет только по разрешённому. Проверено живыми тестами на двух машинах.
- **Мультимодальность без магии.** Голосовые записи и встречи — через
  транскрипцию (с диаризацией) как производные документы; изображения —
  отдельный векторный канал (построен, включается решением владельца);
  видео — поиск по расшифровке с переходами по таймкодам.

| Честный отказ «фактов нет» | гейт в ядре | нет | нет | частично | нет |
| Хранилище = переносимые файлы + пересборка офлайн | да | нет (схема БД) | нет | нет | нет |

| Полностью локальный контур без облака | да | да | да | да | да |

| SSO (AD/LDAP/Яндекс ID) | в планах | есть | есть | есть | есть |

Таблица фиксирует расклад на дату; назначение — честная позиция, а не реклама.

## Дорожная карта

- **Ближайшее:** поиск по видео (расшифровка + таймкоды в цитатах); включение
  канала изображений после выбора модели кодировщика.
- **Корпоративная интеграция:** SSO через AD/LDAP и Яндекс ID (сейчас —
  токены и JWT + группы; интерфейс идентичности уже отделён), коннекторы к
  корпоративным хранилищам как к первичным источникам (файл-каталог, S3,
  корпоративные вики) поверх allowlist-конвейера.
- **Дальше:** агентский доступ (MCP-интерфейс), расширенная мультимодальность,
  офлайн-сборки под закрытые контуры.
