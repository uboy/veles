# Персональный трекер (задачи и заметки)

Статус: v1 (2026-09-28). Компоненты: Telegram-бот (`clients/telegram-bridge/`), библиотека
хранения `tracker.py`, веб-страницы фасада, файлы markdown на диске. Карточка проекта -
трекер ai-tracker (`work/corp-ai-kb/task-corp-ai-kb-architecture-and-prototype.md`).

## Архитектура

```
Telegram (Android/iOS/Desktop)
   │  команды /task /tasks /done /note /notes
   ▼
veles-telegram-bridge (systemd, стенд)  ── напоминалки: поток в процессе моста,
   │  пишет/читает                      проверка каждые 5 мин, сообщение при due ≤ сегодня
   ▼
TRACKER_ROOT = <server-home>/veles-tracker          ◄── git-репозиторий (автокоммит)
   └── <chat_id>/                    на пользователя (id чата Telegram)
       ├── task/task-YYYYMMDD-NN-slug.md
       └── note/note-YYYYMMDD-NN-slug.md

Браузер (ПК/телефон) ──► фасад GET /tracker?token=…   (список задач+заметок)
                        GET /tracker/file/task/<файл>.md?token=…  (исходный md)
```

- **Один источник данных** — каталог markdown на диске. Бот, веб и Obsidian читают одни и
  те же файлы; никаких своих баз у бота и веба нет.
- **Git**: TRACKER_ROOT инициализируется репо при первой записи, каждое изменение - коммит
  (история: кто/когда менял статус). Синк на другие машины - git remote / Syncthing / SMB.
- **Obsidian**: открыть TRACKER_ROOT как хранилище (vault) - файлы со своей YAML-шапкой
  видны заметками, ничего конвертировать не нужно.

## Формат карточки (файл целиком)

```markdown
---
id: task-20260928-02-due-2026-10-03
title: "Разобрать входящие регламенты и завести в базу"
status: todo                # todo | done
created: 2026-09-28T18:15:09
source: telegram            # telegram | transcript | manual
due: 2026-10-03             # опционально
---

Разобрать входящие регламенты и завести в базу due:2026-10-03
(дальше - произвольное тело: детали, чек-листы)
```

- имя файла: `<тип>-<ГГГГММДД>-<порядковый NN>-<ascii-slug>.md`; кириллица в slug
  не используется (слаг из латиницы, иначе хеш `i-<sha1:8>`), кириллица живёт в title/теле.
- `due` ставится тегом в тексте: `due:2026-10-05` или `дедлайн: 2026-10-05`;
  тег попадает в шапку и остаётся в теле.
- `reminded: YYYY-MM-DD` дописывает напоминалка (защита от повторной отправки в тот же день).

## Команды бота

| Команда | Действие |
|---|---|
| `/task текст` | задача; `due:ГГГГ-ММ-ДД` в тексте = дедлайн |
| `/task <длинный текст>` | текст >1500 знаков считается транскрипцией: GLM извлекает задачи списком, создаёт каждую |
| `/tasks` | открытые задачи (done скрыты) |
| `/done часть-id` | закрыть задачу (часть id достаточно) |
| `/note текст` · `/notes` | заметки |

Ограничение: входящее сообщение ≤8000 знаков (лимит Telegram 4096 на ответ - ответ шлётся
кусками). Файлы (.txt/.docx/аудио) бот пока не принимает - в бэклоге.

## Веб-эндпоинты фасада

| URL | Что |
|---|---|
| `/tracker?token=<VELES_API_TOKEN>` | страница: задачи + заметки (done отмечены ✅), ссылки на чат |
| `/tracker/file/task/<имя>.md?token=…` | исходный markdown карточки |

Наверху страницы - ссылки в чат Open WebUI и Telegram (адреса из env
`VELES_WEBUI_URL` и файла `chat-url.txt`, который мост пишет при старте; без хардкода).

## Напоминалки

Поток моста (интервал 5 мин): задачи с `due` сегодня или просроченные и не `done` -
сообщение владельцу в Telegram, метка `reminded` в файле. Для каждого пользователя
(`<chat_id>`) - свой обход, напоминание приходит в его чат.

## Хранение и доступ с других машин

| Канал | Как |
|---|---|
| Obsidian (ПК) | открыть `<server-home>/veles-tracker` как vault: SMB-шара стенд (порт 445) или git clone + плагин Obsidian Git |
| Obsidian (Android) | синк папки (Syncthing/MobileGit) → Obsidian mobile открывает |
| Веб | ссылка `/tracker?token=` с любого устройства в сети |
| Jira | фаза 2 (импорт/выгрузка задач), интерфейс - бэклог карточки |

## Интеграция с транскрибацией (VoxFusion)

Голосовое в боте → скачивание → HTTP-запрос к voxfusion-api (стенд:8500, CPU-only пока
занят GPU) → текст → ответ и/или `/task` из него. Требует сервис voxfusion-api
(строятся отдельно, порт 8500, файлы передаются multipart'ом в API без ручной загрузки
на сервер). Конвейер транскрибации: VoxFusion/GigaAM на стенд.

## Ограничения v1 и бэклог

- статусы только todo/done (без doing/приоритетов) - по потребности;
- напоминания раз в сутки (без точного времени) - cron с временем добавит точность;
- WebUI-экран редактирования задач - бэклог;
- Jira-стык, локальный Windows-сервис транскрибации - см. обсуждение в карточке.
