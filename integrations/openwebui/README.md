# Open WebUI ↔ Veles: загрузка в базу знаний из чата (K16)

Pipe-функция `functions/upload_to_veles.py` превращает чат Open WebUI в
пункт загрузки: пользователь выбирает модель **«Загрузить в базу знаний»**,
прикладывает файл (txt/md/pdf) и пишет название/комментарий. Функция берёт
извлечённый WebUI текст и отправляет его на фасад Veles **лично от имени
пользователя** (заголовок `X-Veles-On-Behalf-Of` + владельческий токен) -
документ попадает в личную группу `user:<email>` и находится поиском базы
знаний. Несколько файлов за раз - каждый отдельным документом; пустой текст
извлечения - честный отказ.

Как файлы попадают в функцию (проверено по исходникам установленной версии
0.11.4, `backend/open_webui/functions.py::generate_function_chat_completion`):
WebUI кладёт приложения в `metadata['files']` и передаёт их pipe-функции
параметром `__files__` **только если он объявлен в сигнатуре** `pipe(self,
body, __user__, __files__=...)`. Элемент списка:
`{"type": "file", "id": ..., "name": ..., "file": {"data": {"content":
"<извлечённый текст>"}}}`. Email пользователя - `__user__["email"]`.
Активная pipe-функция автоматически появляется в списке моделей.

## Требования

- Open WebUI с включёнными плагинами (Functions) и админ-доступом;
- фасад Veles с изменениями K16 (ветка `feature/corp-ai-kb-chat-upload` и
  далее): понимает `X-Veles-On-Behalf-Of` при владельческом bearer;
- владельческий токен фасада (`VELES_API_TOKEN` из `veles-facade.env`).

Заголовок `X-Veles-On-Behalf-Of` фасад принимает **только** с точным
совпадением `Authorization: Bearer VELES_API_TOKEN` - поэтому токен в функцию
набивает админ при установке (Valves), и пользователь не может загрузить
документ «от чужого имени»: email берётся из его сессии WebUI
(`__user__`), а не из текста чата.

## Установка (стенд, сервер - любой инстанс)

1. **Admin Panel** (`http://<хост>:8300/admin/settings` или иконка профиля →
   *Admin Panel*) → раздел **Functions** → **«+»** (New Function / Import
   Functions из файла).
2. Вставьте код `functions/upload_to_veles.py` целиком (при Import -
   выберите файл). Поля подтянутся из фронтматтера: name - «Загрузить в
   базу знаний», id - `upload_to_veles`. Сохраните.
3. Включите функцию тумблером (по умолчанию создаётся выключенной).
4. **Сделайте модель видимой обычным пользователям**: в 0.11.4 функция без
   записи в Models видна только админам («No DB entry ... only admins can
   see unconfigured models» - `utils/models.py::get_filtered_models`).
   Admin Panel → Workspace → Models → «Загрузить в базу знаний» →
   видимость **Public** (или API `POST /api/v1/models/create` с
   `access_grants: [{"principal_type": "user", "principal_id": "*",
   "permission": "read"}]`).
5. На карточке функции нажмите **шестерёнку → Valves** и заполните:
   - `veles_url` - адрес фасада **изнутри контейнера WebUI**. На стенд и в
     ките WebUI ходит на хост через шлюз docker-бриджа:
     `http://host.docker.internal:8400` (тот же хост, что в настройках
     OpenAI-соединения WebUI);
   - `veles_token` - `VELES_API_TOKEN` фасада;
   - `wait_seconds` / `poll_interval_seconds` - сколько ждать окончания
     обработки документа (по умолчанию 90 с, шаг опроса 2 с).
6. В чате: выбрать модель «Загрузить в базу знаний», прикрепить файл,
   написать название (оно станет названием документа; у одного файла -
   название из сообщения, у нескольких - из имён файлов).

Проверка установки: в списке моделей (под обычным пользователем, не
админом) появилась «Загрузить в базу знаний»; через Admin Panel →
Functions → Valves видно заполненные значения.

Нюанс версий 0.11.x: фоновые задачи WebUI (генерация поисковых запросов по
приложенным файлам, теги) вызывают ту же модель - функция различает их по
параметру `__task__` и не выполняет загрузку (без этого документ получал
название служебного промпта).

## Живая проверка (стенд, 2026-09-30)

Установлена через Admin API (`/api/v1/functions/create` → `/toggle` →
`/valves/update`), живой тест - `POST /api/chat/completions` с файлом
(см. `evals/results/2026-09-30-k16-chat-upload.md`): документ появился в
фасаде личным, поиск находит, ответ функции человеческий.

Удаление/откат: Admin Panel → Functions → удалить `upload_to_veles`
(или `DELETE /api/v1/functions/id/upload_to_veles/delete`). Обратимо,
прод не трогает.
