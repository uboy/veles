# Eval: сквозная валидация LDAP-входа (ldap-identity, фаза 2), 2026-10-12

## Что доказывается

Корпоративный вход LDAP/AD работает сквозным сценарием ИБ-службы на живом
приложении: доменный логин/пароль -> jwt с группами из каталога -> вопрос
видит только документы своих групп; отзыв группы в каталоге виден при
следующем входе; старый токен протухает по TTL; без настройки LDAP маршрут
отключён и текущие режимы не затронуты. Реализация - коммит d150fdc
(ветка feature/ldap-identity): veles/policy/ldap_identity.py, маршрут
POST /v1/auth/ldap в veles/api/app.py.

## Метод

Живой контур, без внешних сервисов:

1. In-process LDAP-сервер на ldaptor 21.2.0 (Twisted reactor 26.4.0 в
   фоновом daemon-потоке, ephemeral-порт на 127.0.0.1): дерево «корпорация» -
   2 пользователя (ivanov, petrov) x 2 группы (corp-all, otdel), членство в
   обеих формах: memberOf на записи пользователя (форма AD) и posixGroup с
   memberUid (RFC 2307) - обе проходят чтение групп.
2. Маппинг VELES_LDAP_GROUP_MAP: cn=corp-all -> группа veles «all»,
   cn=otdel -> группа veles «otdel» (отдел). Конфиг групп veles
   (groups.json): определения all + otdel, members пусты - состав приходит
   из каталога через claims подписанного jwt.
3. Приложение - настоящий create_app() под TestClient (fastapi 0.141.1,
   httpx 0.28.1, python 3.11.9, numpy 2.2.6), identity_mode=jwt,
   VELES_LDAP_JWT_TTL_S=10 (короткоживущий). Эмбеддер - детерминированный
   hashing (как в тестах ingest), dim = EMBED_DIM: валидация не грузит
   модели и не зависит от сети; фильтр по группам от эмбеддера не зависит.
4. Документы загружены ЗАРАНЕЕ через настоящий цикл: POST /v1/documents
   (bearer владельца) -> очередь -> парсер -> индекс (живой апсерт + overlay):
   «Регламент закупок отдела» в группу otdel, «Коучинг и мотивация» в all.
5. Вопросы - POST /v1/knowledge/query с заголовком X-OpenWebUI-User-Jwt
   (токен входа), без LLM; проверяются evidence (фильтр по группам).

## Замечания по запуску (для повторения)

- **Грабли импорта:** при `python evals/...` sys.path[0] - каталог `evals/`,
  и без явного `sys.path.insert(0, <корень репо>)` импортируется
  УСТАНОВЛЕННЫЙ в site-packages veles 0.1.0 (без коммита ldap-identity):
  маршрут /v1/auth/ldap отсутствует -> все входы 404. Скрипт вставляет корень
  по `__file__` (захардкоженных путей нет) и перед create_app гейтится
  `ldap_identity.is_configured()`.
- ldaptor-квирк: фильтр (objectClass=*) матчит только записи с заполненным
  атрибутом objectClass - он задан у каждой записи дерева (как и в
  tests/test_ldap_identity.py).
- VELES_QUEUE_PARSE_TIMEOUT_S=0 обязателен (изоляция разбора отдельным
  процессом выключена, как в tests/conftest.py): spawn-процесс не наследует
  подстановки окружения.
- Маркеры документов в выдаче сравниваются без учёта регистра: парсер
  сохраняет регистр заголовка/первой буквы предложения.
- TTL jwt для проверки (г) - 10 c: проверки (а)-(в) укладываются в срок
  жизни первого токена, ожидание истечения - только остаток до exp.
