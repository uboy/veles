# Eval: K19 - единая модель чата WebUI «загрузка + вопросы» (veles_knowledge)

Дата: 2026-09-30 · Ветка: `feature/corp-ai-kb-unified-chat` (от main 33a109f) ·
Worktree: `~/proj/veles-wt-k19` (Windows-хост владельца)

Запрос владельца 30.09: «нельзя сделать одну модель - если загружаешь документ,
она добавляет в личное хранилище; если спрашиваешь - отвечает по базе?».
Бриф: `docs/plan/briefs/2026-09-30-k19-unified-chat-model.md`.

## 1. Что сделано

`integrations/openwebui/functions/veles_knowledge.py` (новая pipe-функция,
WebUI 0.11.4) - одна модель на оба сценария:

- **файл(ы), без текста вопроса** - загрузка в личное хранилище:
  POST /v1/documents с `X-Veles-On-Behalf-Of` = email из `__user__`
  (владельческий токен - в valves, пользователь его не видит); название
  документа - имя файла (текст сообщения при файлах трактуется как вопрос);
  подтверждение по каждому файлу, ошибки фасада - человеческой фразой;
- **только текстовый вопрос** - POST /v1/knowledge/query, рендер цитат тот
  же, что у veles-knowledge фасада: сноски [n] -> `[«название»](ссылка)`,
  блок «Источники:» с файлом и строками, честный abstain с причиной;
- **файлы + вопрос** - сначала загрузка всех файлов, затем ответ; если
  джобы не успели - примечание «ответ дан по текущей базе»;
- guard `__task__` (прецедент K16), запрет редиректов (`_NoRedirect`),
  инъекционный `_OPENER`, multipart stdlib-средствами - паттерны K16.

Старая `upload_to_veles.py` не тронута (совместимость до переключения в
деплое). Дефолты valves - пустые строки (`veles_url`, `veles_token`,
`veles_public_url` - адрес фасада для ссылок из браузера пользователя,
пусто -> `veles_url`).

## 3. Живая приёмка (стенд, тестовый контур, прод не тронут)

Контур (по прецеденту K16, всё удалено после проверки): фасад ВЕТКИ на
`:8401` из git-архива ветки (`/tmp/k19-pytest`), `VELES_DATA=/tmp/k19-veles-data`
(сид: демо-индекс K15, 5 документов ООО «Ромашка» + 1 документ через API),
токен тестовый, LLM синтез ВЫКЛЮЧЕН (env VELES_LLM_* не заданы - ответы
extractive; цитаты и рендер от этого не зависят); WebUI - ОТДЕЛЬНЫЙ контейнер
`open-webui-k19` на `:8301` (образ 0.11.4, свой volume `open-webui-k19`).
Прод: фасад `:8400` и WebUI `:8300` не тронуты (healthz/version зелёные до
и после).

Установка: admin signup -> user `ivanov@veles.local` ->
`POST /api/v1/functions/create` (id `veles_knowledge`, name «База знаний
(Veles)») -> toggle -> valves (veles_url=http://host.docker.internal:8401,
veles_token=тестовый, veles_public_url=http://<bench-lan-ip>:8401) ->
`POST /api/v1/models/create` с read-грантом `principal_id: "*"`.

Кейсы (живые `POST /api/chat/completions` от имени ivanov):

1. **Модель одна в списке**: `GET /api/models` ivanov ->
   `["veles_knowledge"]` - ровно одна.
2. **Только вопрос** («Сколько дней ежегодный отпуск?») -> ответ по базе
   (извлечение, 1.1-1.4 про 28 календарных дней) + «Источники:» 5 ссылок
   вида `[«Регламент отпусков ООО Ромашка»](http://<bench-lan-ip>:8401/
   v1/source/...?token=...&node=...#n-...)` с файлом и строками.
3. **Только файлы** (txt + md одним сообщением) -> «✅ Документ
   «регламент_премий» загружен в вашу личную базу знаний: доступен в
   поиске (группа доступа - личная, ivanov@veles.local).» - то же для md.
   На фасаде: манифесты
   `ivanov@veles.local/регламент_премий.txt` и `.md` -
   `access_groups: [user:ivanov@veles.local, personal]`,
   `ingested_by: ivanov@veles.local`, r1; L0 в
   `uploads/ivanov@veles.local/`; в `uploads/ingest-jobs.jsonl` ровно один
   `created` на документ (названия из имён файлов, без служебных промптов).
4. **Файл + вопрос** («Норма управляемости у руководителя отдела?» + txt)
   -> подтверждение загрузки, затем ответ по базе с цитатой на сид-документ
   «Норма управляемости».
5. **Пустое сообщение** -> «Задайте вопрос текстом - отвечу по базе знаний
   со ссылками на источники. Или прикрепите файл (txt, md, pdf)...».
6. **401 фасада**: valves veles_token=WRONG-token -> «⚠ Фасад отклонил
   токен (401) - проверьте Valve veles_token модели (администратору).»;
   valves восстановлены.
7. **Guard `__task__` вживую, невакуусно**: реальный маршрут фоновой задачи
   `POST /api/v1/tasks/queries/completions` (тот же, что дёргает WebUI по
   файлам; форма сверена по исходникам контейнера 0.11.4) с файлом ->
   200, ответ функции пуст, загрузки НЕТ («upload: нет (guard держит)»).
8. **Ссылка цитаты из браузера-хоста**: `GET` по ссылке из ответа с
   Windows-хоста на `<bench-lan-ip>:8401/v1/source/...` -> 200, HTML-страница
   источника.

После приёмки контур снесён: контейнер и volume удалены, фасад :8401 убит,
`/tmp/k19-*` удалены; прод-проверки: `:8400/healthz` ok, index_loaded true,
`:8300` version 0.11.4.

## 4. Границы (не проверено / решения владельца)

- **Браузерный UI-тест (клики в WebUI)** - MANUAL, как в K16: все кейсы
  через API реалистичными payload'ами (файлы как шлёт фронтенд).
- **Abstain вживую не достигнут**: демо-корпус мал, фасад на посторонние
  вопросы («борщ», «НДС при импорте») даёт answer с натяжкой - это домен
  калибровки K12, не K19; abstain-рендер (честный отказ с причиной и
  подсказкой) покрыт юнит-тестом на контракте фасада.
- **LLM-синтез в тесте выключен** (extractive): инлайн-подстановки сносок
  [n] -> [«название»](ссылка) в тексте синтеза на живом контуре не
  воспроизводились (их делает GLM в проде); замена покрыта юнит-тестом,
  формат совпадает с `render_chat_content` фасада. Прод-WebUI использует
  GLM - включится сам, valves те же.
- **Нет email в `__user__`** - юнит-тест; через API WebUI пользователь без
  email нереализуем.
- **Токен в ссылках (вопрос владельцу)**: ссылки цитат строятся как у
  veles-knowledge в static-режиме - с `token=` (владельческий токен) в
  query. Это паритет с текущим продом (Telegram и web-чат уже отдают
  такие ссылки), но в многопользовательском контуре каждый пользователь
  получает владельческий токен ( act-as!). Альтернатива - подписанные
  ссылки (link_secret) или рендер на стороне фасада: отдельное решение
  координатора до корпоративного деплоя.
- **ACL вопросов в identity-режимах**: запрос /v1/knowledge/query идёт с
  владельческим bearer -> admin-личность (видит всё, включая чужие личные
  документы). Это свойство текущего veles-knowledge-подключения WebUI, не
  новое в K19; act-as для query фасад не поддерживает (только documents).
  Для корпоративного режима - отдельная фаза.
- **Деплой**: обновление кита (deploy/kit) и переключение прод-WebUI
  (:8300 стенд) с пары «veles-knowledge + upload_to_veles» на одну модель -
  отдельная фаза координатора; старая функция не удаляется до
  переключения.
