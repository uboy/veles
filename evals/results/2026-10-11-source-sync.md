# Eval: сквозная валидация коннектора №1 sync (connektor-papka, фаза 2), 2026-10-11

## Что доказывается

Сценарий заказчика JTBD P0-1 на живом коде (не моки): `veles sync --root <dir>`
приводит канон и живой индекс к состоянию каталога-источника — новые файлы
ингестятся, правка файла становится ревизией r2 (старая в архиве, K3),
удаление — tombstone (K10), повторный sync без изменений — ноль дельты.
Источник строго читается. Проверка идёт ЧЕРЕЗ гибридный поиск, а не по
состоянию файлов канона.

## Метод

- Код: ветка feature/source-sync (worktree veles-sync), коммит 9014452
  (`veles/ingest/sync.py`, `cmd_sync` в `veles/cli.py`). План:
  `docs/plan/connektor-papka/plan.md` (фаза 2), бриф:
  `docs/plan/briefs/2026-10-11-connektor-papka.md`.
- Скрипт: `evals/source-sync-validate.py`; команда запуска из корня
  репозитория: `python -u evals/source-sync-validate.py`. Он сам создаёт
  временные `VELES_DATA` и каталог-источник (system temp, env выставляется ДО
  импорта конфига), бутстрапирует пустой индекс паттерном `cmd_add`
  (build_index + save в `<VELES_DATA>/index`) и убирает за собой.
- Инфраструктура настоящая: эмбеддер intfloat/multilingual-e5-small
  (продовая модель EMBED_MODEL, локальный кэш HuggingFace), векторный бэкенд
  faiss (`make_store`), CLI-путь `cmd_sync` целиком (файловый лок sync_lock +
  build_plan + apply_plan + обновление живого индекса upsert_document +
  append_overlay / tombstone_document). Поиск — `hybrid_search` по СВЕЖЕЙ
  загрузке индекса с диска (`load_index` применяет overlay: семантика
  «рестарта фасада», не память процесса sync).
- Каталог: 3 файла с непересекающейся лексикой — `otchet-q3.md`,
  `prikaz-otpuska.txt`, `instrukciya-vpn.md`. Критерий нахождения — маркерная
  подстрока в текстах выдачи top_k=8.
- Все проверки — assertions в скрипте (негатив обязан падать по своей
  причине: assert с перечнем фактической выдачи в сообщении); финальная
  строка `VALIDATION-PASS`.

  формат pdf коннектором заявлен, но в этом eval не прогонялся (pdf идёт
  существующим docling-конвейером очереди — его изоляция покрыта юнит-тестами).

  не входят; юнит-покрытие sync — tests/test_source_sync.py (458 строк,

## Дополнение 12.10: перепрогон на финальном HEAD (37b5178)

После трёх раундов правок по ревью скрипт валидации НЕ перезапускался (гейт
workflow ответил из журнала возобновлённого прогона). Ручной перепрогон
нашёл два рассинхрона eval-скрипта с эволюцией кода, оба исправлены в этом
же коммите:

1. Парсер итоговой строки CLI держался за старый формат («удалено=N (узлов
   выведено...)») - раунды правок добавили поле «доведено до индекса».
   Разбор переделан на устойчивые пары «поле=число|:число».
2. Шаг (г) ожидал, что на нулевой дельте применение не запускается. По
   фиксам ревью семантика изменена осознанно: apply на нулевой дельте
   доводит до индекса незакрытые намерения (самолечение после падения
   «канон обновлён, индекс нет»); ожидание заменено на «все счётчики
   итоговой строки по нулям» + прежнюю проверку отсутствия новых событий
   в журнале ингеста.
