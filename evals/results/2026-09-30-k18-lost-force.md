# Eval: K18 - статусы «утратил силу» (метка узла при индексации + плашка в цитатах)

Дата: 2026-09-30 · Ветка: `feature/corp-ai-kb-lost-force` (от main 33a109f) ·
Worktree: `~/proj/veles-wt-status` (Windows-хост владельца, локально)
Бриф: `docs/plan/briefs/2026-09-30-k18-lost-force-status.md`

Реализация: детектор «утратил силу» / «не подлежит применению» по тексту узла
пишет `lost_force: true` в node_meta при индексации (build_index И
инкрементальный upsert_document); ранжирование не меняется, узел не скрывается;
цитаты JSON несут `lost_force`; рендеры ставят плашку «⚠ Норма утратила силу»
перед цитатой (чат-рендер фасада render_chat_content, Telegram-мост, CLI).

## 1. Юнит-тесты (без моделей, детерминированный hashing-эмбеддер)

```
$ python -m pytest tests -q                       # полный набор
312 passed, 2 skipped, 2 warnings in 49.07s

$ python -m pytest tests -q --ignore=tests/test_lost_force.py   # база без K18
290 passed, 2 skipped, 1 warning in 44.75s

$ python -m pytest tests/test_lost_force.py -q
22 passed in 0.84s
```

22 новых теста (файл `tests/test_lost_force.py`):

- **Позитив детектора**: формы «утратил/утратила/утратили/утратило силу»,
  «не подлежит применению», любой регистр; контентный узел «Часть вторая
  утратила силу с 2 июля 2021 г.» матчится.
- **Позитив индексации**: настоящий `build_index` на tmp-каноне из двух md -
  узел с «Раздел 2 утратил силу...» получает `lost_force=True`, соседний узел
  того же документа («Суточные...») и обычный документ - `False` (метка на
  УЗЕЛ, не на документ).
- **Позитив инкрементального пути**: `upsert_document` (K4-загрузка) ставит ту
  же метку - пользовательская загрузка меченого документа видна с меткой без
  плановой пересборки.
- **Негатив рендера**: у обычного узла плашки нет (assert `LOST_FORCE_PREFIX
  not in content` - падает по своей причине, если плашка ставится безусловно).
- **Негатив-совместимость «старый индекс»**: мета без поля `lost_force`
  (симуляция meta.json до K18) - поиск работает, `lost_force=False`, плашки
  нет, ошибок нет.
- **Нейтральность ранжирования**: одинаковые узлы с флагом и без дают
  идентичные `(rrf, rrf_base, dense_rank, bm25_rank)` и порядок - флаг меняет
  только цитату.
- **API JSON**: `/v1/knowledge/query` несёт `lost_force: true/false` в цитатах
  (новое поле в существующем списке - старые клиенты игнорируют).
- **Синхронизация плашки**: `tg_format.LOST_FORCE_PLATE ==`
  `retriever.LOST_FORCE_PREFIX` (байт в байт) + pass-through тест: конвертер
  Telegram-HTML доносит плашку из render_chat_content без искажений.

## 3. Бенч golden/rrncb50 - не перегонялся (граница)

Мандат этой сессии: GPU-хосты не трогать, бенч-инфраструктура стенд вне периметра.
Нейтральность ранжирования доказана юнит-тестом на уровне scоров: `lost_force`
читается из node_meta ТОЛЬКО при формировании цитаты (retriever.py, поля
Citation); в dense/BM25/RRF/codex-boost путь флага нет - деградация бенча
невозможна по построению. Рекомендация: при следующем плановом перегоне бенча
зафиксировать golden/rrncb50 как контроль (ожидается байт-в-байт совпадение с
текущими цифрами K14/K12).

## 4. Ограничения (честно)

- **Метка по тексту узла, не по официальному статусу документа.** Официальный
  статус акта (источник pravo.gov.ru) - будущая фаза (бриф, research).
- **Прод-индекс получит метки при следующей плановой пересборке**
  (`python -m veles index`, ~27 мин на 158k узлов на стенд). До пересборки
  прод-цитаты считаются действующими (lost_force=False) - код на старом индексе
  работает без ошибок (п. 2.3). Инкрементальные загрузки (K4/CLI add) получают
  метку сразу.
- **tg_format держит плашку константой, а не импортом**: контейнер моста
  (Dockerfile.bridge) не содержит пакет veles - только httpx; мост получает
  готовый markdown из render_chat_content через chat/completions, плашка
  доезжает как текст. От расползания двух констант - тест
  `test_lost_force_plate_sync`. Функция `tg_format.lost_force_prefix` - для
  будущих прямых рендеров цитат на стороне моста.
- Пустышки-заглушки «Утратил силу.» (парсинг консолидированных актов)
  детектором метятся, но в выдачу их режет отдельный K12-фильтр
  (`is_junk_node`) - механизмы не связаны (тест
  `test_detector_is_content_level_not_junk_gate`).

## Независимое ревью и фикс (тот же заход)

- Ревью: FAIL с одним P1 - детектор ловил отрицание «не утратил(а/о/и) силу»
  как положительное («Положение не утратило силу и действует» -> True,
  воспроизведено ревьюером). Безопасность (XSS/ReDoS/инъекции через
  node_meta), нейтральность ранжирования, обратная совместимость -
  проверено ревьюером, чисто.
- Фикс: lookbehind `(?<!не )` перед глагольной группой + причастная
  официальная форма `утративш[а-я]+ силу` (P2 ревью: «признан утратившим
  силу» ранее молчал). На «не подлежит применению» lookbehind не
  распространён (там «не» - часть фразы утраты).
- Тесты после фикса: test_lost_force.py 27 passed (было 22; +2 позитивных
  причастия, +3 негатива на отрицание); полный прогон 316 passed,
  2 skipped, 1 failed - предсуществующий виндовый флейк
  test_tracker.py::test_atomic_write_reader_sees_whole_file (PermissionError
  в os.replace при файловом прогоне; файлы вне K18; одиночный прогон
  1 passed). Флейк к K18 не относится, зафиксирован отдельно.
- Девиация tg_format (константа + тест-синхронизация вместо общей функции:
  в контейнере моста нет пакета veles, Dockerfile.bridge ставит только
  httpx) - принята ревьюером как обоснованная.
