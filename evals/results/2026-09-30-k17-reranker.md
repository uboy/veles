# Eval K17: reranker (опциональный пост-этап hybrid_search)

Дата: 2026-09-30. Эпик: corp-ai-kb. Ветка `feature/corp-ai-kb-reranker`,
worktree `veles-wt-rerank` (база 33a109f = main + брифы K17/K18). Бриф:
`docs/plan/briefs/2026-09-30-k17-reranker.md`. Исполнение: работа продолжена
после обрыва предыдущей сессии (незакоммиченный черновик reranker.py/правки
config.py разобраны, доработаны, докоммичены).

## Что сделано

- `veles/retrieval/reranker.py`: CrossEncoder-скоринг пары «вопрос-фрагмент»
  (sentence-transformers), ленивая загрузка с процессным кэшем, fail-open
  (ошибка загрузки/инференса = лог-warning и входной порядок, ответ не роняется),
  негативный кэш провалов загрузки (повторный запрос не дёргает сеть, сервис
  живёт без реранка до рестарта; снять - reset_cache()), замер латентности этапа
  в лог (`veles.reranker`), инференс CPU-only (device="cpu" в коде).
- `veles/config.py`: `VELES_RERANKER_MODEL` (env, пусто/не задано = ВЫКЛЮЧЕНО,
  дефолт), `RERANK_CANDIDATES = 25` (глубина пула под rerank, бриф K17).
- `veles/retrieval/retriever.py`: интеграция в hybrid_search - включённый
  реранкер забирает верхние `rerank_candidates` узлов RRF (ПОСЛЕ буста,
  ПЕРЕД усечением top_k), пересортировывает, наверх идут топ-k. Органические
  rrf/rrf_base не тронуты (confidence abstain-гейта и warn_conflict считаются
  как раньше); диагностика - новые поля `Evidence.rerank_score`,
  `rerank_rank_hybrid`. Выключено - пул не строится и модуль не импортируется
  (ноль регрессии). Новый kwarg `rerank_candidates` (None = конфиг).
- `veles/api/app.py`: прогрев модели в фоновом потоке старта (`preload()`,
  паттерн прогрева эмбеддера; пустой env - no-op, порт не блокируется).
- `evals/synth-bench/rerank_latency.py`: замер латентности (baseline / пул-25 /
  rerank / e2e) на вопросах golden+rrncb50+codex-check.
- Тесты `tests/test_reranker.py` (12): позитив (порядок меняется
  детерминированно по моку-скореру, пул шире топ-k), негатив (дефолт пуст =
  rerank не вызывается вовсе), fail-open (исключение инференса, провал загрузки
  + негативный кэш), ties, усечение top_k, preload no-op/не роняет.

Полный 128-вопросный прогон не выполнялся СОЗНАТЕЛЬНО: при ~56 с на вызов и

### bge-reranker-base (278M): блокер - веса не докачались

Три попытки загрузки с HuggingFace (snapshot + point-загрузка pytorch_model.bin):
сеть дросселируется после ~4.5 ГБ, скачанных за сессию: в кэше 534 МБ
(токенизатор + 2 частичных onnx-блоба), файл весов pytorch_model.bin - 0 байт
(.incomplete с 16:33). Латентность base локально НЕ измерена. По опубликованным
характеристикам (в 2 раза меньше параметров, ~2-4x быстрее v2-m3) ожидание на
этом хосте - десятки секунд на вызов, т.е. тоже мимо бюджета 1.5 с; подтвердить
замером на стенд.

### Вывод по латентности (локальный хост)

1. Сам ретрив не дорого стоит: hybrid_search p50 41-46 мс (и на пуле 25).
2. Cross-encoder rerank на CPU ЭТОГО хоста не проходит бюджет <1.5 с ни одной
   из моделей (v2-m3 - на ~50x). Рекомендация владельцу: решать включение по
   стенд-замеру (серверный CPU); если и стенд-CPU не проходит - варианты: GPU
   (заняты до 02.10), меньшая модель, или defer. Подмены модели/хоста в
   проде без решения владельца не делалось.
3. Фасад при включённом реранкере получает разовую задержку старта на
   preload (здесь 47 с для v2-m3 из page cache; в фоне, порт не блокируется).
